Privacy

This is a plain-language summary, not legal advice.

Effective date: November 25, 2026.

There is no account. The app does not upload your profile, loadouts, or library to a server it runs.

On this device

An IndexedDB database named kitcheck holds four stores. Profile stores your state, ZIP, body, user type, whether gear is issued, age, the age gate derived from that age, units, theme, height, weight, and size notes for helmet, plate, belt, boot, and glove. Loadouts store the kit name, slots, part builds, mod presets, weight budget, owned marks, and bag assignments. Library stores items you add, including a tag, a price you typed, fit notes, and a photo if you attached one. Reminders store a name, a kind, and a date you typed.

localStorage holds the theme, the cart, the figure background, prices you have already seen, a demo flag, a timeline of items you marked owned, whether the tour is on, the tradeoff slider, whether you dismissed starter kits, and the checked rows of a kit checklist.

The service worker can keep app files in the browser cache so a page you have loaded can open offline. Product photos from other sites can be cached too, when the image is under 1 megabyte, up to 200 images.

You can download a JSON file of the profile, loadouts, library, and reminders, or import one. That file goes where you save it. You can also clear the on-device data from the profile screen.

What is sent

Opening the app requests its own files, including the example price file, from the same site that served the page. Those requests stay on that site.

Build assist is off unless the site was built with an address for it. In this project that address is empty, so the button is hidden and the app does not contact a build-assist server. If a build turns it on, Ask sends the words you typed and catalog rows (an id, a name, a price, and a weight) to that address.

Share puts the loadout in the link’s hash on this device: the name, preset, slots, part builds, weight budget, and any hand-entered item name and fit notes. Photos are left out. Fit fields whose names contain “price” or “zip” are left out. The profile, age, and ZIP are not in that link. Whoever you send the link to can open that loadout. The app does not upload the link.

A barcode scan uses the camera on this device and compares the code to the catalog stored here. A code that is not in that list shows no data. The picture from the camera is not sent by the app.

A buy link, a store page, or a maker page opens only when you choose it. In this build the price file’s links are on example.com, and the dollar amounts in the builder are example prices. Maker pages use the address stored on that catalog row. Some ammunition items can open ammoseek.com in a new tab after the same age check as the other ammunition links. The app does not fetch that site on its own.

Cookies, analytics, and contact

The app code does not set cookies. It does not include an analytics tag. A site you open from a link can set its own cookies. This app does not read those.

Contact is the support address support@kitchecktactical.com. The form opens your email app. The message includes the kind of note, the app version, the loadout id, a reply address if you typed one, and the text you wrote. It is sent when you send the email.
